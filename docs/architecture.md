# 小说写作台的请求路径

1. 浏览器获取身份，从 IndexedDB 打开这个作者的作品及上次编辑的章节。日常编辑只写入浏览器书架。
2. 作者要求续写或核对时，浏览器从本书选择当前章和前文材料，加入已经登场的人物和在此处已知的线索。较长来源分别截取，以保留章末。
3. FastAPI 验证身份和权限，运行唯一的小说协作编辑。模型接收作品快照与作者要求。每次新建议有自己的线程，同一次重试使用幂等键。
4. 返回的续文先展示在预览中。只有作者主动采纳，浏览器才将其追加到正文。前文核对意见供参考。
5. 服务端用独立的运行记录处理恢复、保留期限、策略和审计。开发环境可使用 SQLite，生产部署使用 Redis 和 MySQL。
